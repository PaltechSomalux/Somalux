- Creates `first_login_tracking` table

- Creates 3 performance indexes
- UNIQUE constraint (one record per user)

**Fields:**

- `location` (TEXT) - Reserved for future GeoIP use
- `created_at` (TIMESTAMP TZ) - Record creation time

## 🎯 What The System Does

### Automatic Tracking
1. User logs in via `POST /api/user/session/login`
2. System checks if first login record exists
3. If FIRST LOGIN → Creates record with all data
4. If SUBSEQUENT LOGIN → Skips (UNIQUE constraint prevents duplicate)
5. Returns success (non-blocking, doesn't slow login)

### Data Captured (One Time Per User)
```
✅ first_login_at     2026-01-24T10:30:45.123+03:00
✅ first_login_date   2026-01-24
✅ first_login_time   10:30:45+03:00
✅ device_type        mobile (or desktop/tablet)
✅ browser            Chrome (or Firefox/Safari/etc)
✅ operating_system   Android (or iOS/Windows/etc)
✅ ip_address         203.0.113.42
✅ user_agent         Full browser string
```

### Security
```
✅ RLS enabled - Users see only their own data
✅ Admins can see all first logins
✅ UNIQUE constraint - One record per user
✅ Immutable - Users cannot modify their record
✅ Fire-and-forget - No blocking
```

### Performance
```
✅ Indexed on: user_id, first_login_date, created_at
✅ Non-blocking - Uses fire-and-forget pattern
✅ UNIQUE constraint prevents duplicate inserts
✅ Graceful degradation - Login succeeds even if tracking fails
```

## 📊 Query Examples

### Get all users' first login info
```sql
SELECT p.email, f.first_login_date, f.device_type, f.browser
FROM profiles p
LEFT JOIN first_login_tracking f ON p.id = f.user_id
WHERE f.id IS NOT NULL
ORDER BY f.first_login_date DESC;
```

### Device breakdown
```sql
SELECT device_type, COUNT(*) as count
FROM first_login_tracking
GROUP BY device_type
ORDER BY count DESC;
```

### First logins today
```sql
SELECT * FROM first_login_tracking
WHERE first_login_date = CURRENT_DATE
ORDER BY first_login_time DESC;
```
